# Review / Complaint Recovery

## When to use
Trigger on: negative review, complaint, unhappy customer, service recovery.

## Workflow
- [ ] 1. Read the actual complaint/review in full — don't summarize before understanding it
- [ ] 2. Draft a response that: acknowledges the specific issue (not generic "sorry for
      any inconvenience"), is swift and genuinely empathetic, and proposes a concrete,
      fair gesture if one is warranted
- [ ] 3. Save as a draft (email reply, or a draft for the human to paste as a public
      review response, depending on where the complaint landed)

## Copy rules
- Specific beats generic — reference exactly what went wrong.
- A well-handled recovery can leave a customer more loyal than if nothing went wrong
  (the "service recovery paradox") — but only with a genuinely fair outcome, not a
  token gesture.
- No corporate deflection language.

## Boundaries
- Never send or post publicly without review — a bad recovery response is worse than
  a slow one.
